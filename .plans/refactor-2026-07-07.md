# Refactor plan — paideia-as v0.17 diminishing returns (2026-07-07)

**Motivation.** The autonomous loop is entering a regime where each feature
addition surfaces 3–7 latent regressions in unrelated code paths. Root-cause
survey identified a small set of structural smells that cause this pattern:

- Diagnostics fire and are silently discarded, then bulk-drain surfaces years
  of ignored T-codes at once.
- Populator passes in `lower.rs` are ordered by call sequence with no manifest;
  each new populator can silently invalidate an implicit dependency.
- `cmd_build::run` is a 1,448-line god-function holding every pipeline phase
  in one scope — new phases interact non-locally with 10+ variables.
- Multiple parallel diagnostic buffers (`EmitWalker.diagnostics`,
  `resolve_diags`, `opt_sink`, several walker-local `Vec<String>`) exist
  outside the canonical `DiagnosticSink` bus.
- Match/enum dispatch codegen assumes the scrutinee is pre-materialized in a
  register; no real load is emitted — const-fold accidents flip correctness.
- Manual `estimated_offset` advances that bypass the canonical `emit_inst`
  helper (documented drift bug from #985/#986 reappearing).
- Loop-context stack is push-only; `pop_loop_context` has zero callers.

**Baseline state at plan authoring (2026-07-07).**
- Parser lib: 331 passed / 0 failed.
- Elaborator lib: 816 passed / 0 failed / 10 ignored.
- paideia-as (integration + lib): 258 passed / 0 failed.
- Workspace: 452 passed / 1 failed / 17 ignored — one pre-existing stale
  snapshot (`sarif__snapshot_multi_diagnostic`) unrelated to this refactor.
- One uncommitted test file had a missing 5th arg to `lower_ast_to_ir`
  (`pa_r15_009c_jump_table_fixture.rs:296`) — patched pre-baseline (step 0).

The followup notes named a `emit_walker.diagnostics()` drain at
cmd_build.rs:1093-1127 that regressed 7 files. That drain is NOT present in
the current tree; only a `resolve_diags` drain at 1148-1200 exists. That
drain does compile & pass — but it string-parses `T####:` prefixes out of
`Display`ed diagnostic messages, falls back to unregistered code `700`, and
loses structural fields. Retiring the string parse is Step 2 below.

## Stopping rule

**Step 3 is the mandatory floor.** After Step 3, `EmitWalker` no longer holds
its own `Vec<String>` buffer that can be silently ignored; every T-code the
walker can emit is a structured `Diagnostic` routed through the same
`DiagnosticSink` as `LinearityWalker`/`EffectRowWalker`/`CapWalker`/
`UnsafeWalker`. This alone eliminates the "silent-fire-then-discard →
regression when drain gets wired" class that produced the #1082 debacle.

If time forces a partial land, land through Step 3 and stop.

## Plan

Each step lists: (files touched) · (invariant restored/introduced) · (bug
class eliminated) · (test strategy) · (reversibility).

### Step 0 — Baseline hygiene (DONE)

- File: `crates/paideia-as-elaborator/tests/pa_r15_009c_jump_table_fixture.rs:296`.
- Add missing `&EnumRegistry::empty()` to align with the 5-arg
  `lower_ast_to_ir` signature.
- Bug class: pre-existing "one test file forgotten in a signature migration."
- Test strategy: workspace test build now succeeds; test still passes.
- Reversibility: single line.

### Step 1 — Deferred to follow-ups

- Original intent: retire orphan `OptDiagSink`.
- Reason deferred: `OptDiagSink` is a distinct type (`Vec<OptDiagnostic>`
  with `pass`+`message` string pair) and has ~15+ live emission sites in
  the optimizer passes. Converting requires either registering an O-code
  range in `catalog.toml`, or an eprintln (constraint-forbidden), or a
  broader signature change across `OptPass::apply(...)`. That is scope
  surprise for a first step. Moved to the "recommended follow-ups"
  section so we do not skip a large invariant boundary at the beginning.

### Step 2 — Retire string-parsed T-code drain for resolve_var_operands

- Files: `crates/paideia-as/src/resolve_var_operands.rs`,
  `crates/paideia-as/src/cmd_build.rs` (~1148-1200).
- Change `resolve_var_operands` signature from `&mut Vec<String>` to accept
  a typed `Diagnostic` collector (`&mut Vec<Diagnostic>` or
  `&mut dyn DiagnosticSink`).
- Delete the `msg_str.find(':')` parse and the `700` fallback fabrication.
- Invariant introduced: T-codes never round-trip through a `Display` string.
- Bug class: silent T-code downgrade to unregistered code 700; loss of span
  info during string round-trip.
- Test strategy: all four suites; direct unit test that a T0528 emitted by
  `resolve_var_operands` reaches the sink with code preserved.
- Reversibility: contained; caller signature change touches ~5 sites.

### Step 3 — Introduce a typed diagnostic pipe on EmitWalker (FLOOR)

- Files: `crates/paideia-as-elaborator/src/emit_walker.rs`,
  `crates/paideia-as-elaborator/src/lib.rs`,
  `crates/paideia-as/src/cmd_build.rs`.
- Discovery during Step 3 investigation: there are 65 `self.diagnostics.
  push(...)` sites across 8 emit_*.rs files, each embedding a `T####:`
  prefix in a `format!` string. Wiring a naive drain that parses the
  prefix and promotes to `Severity::Error` would flip `preview = true`
  in `cmd_build::run` (line 1974) for any test whose scrutinee accidentally
  triggers a latent fire — the same failure mode as the #1082 debacle.
- Retargeted step: introduce a `Vec<Diagnostic>` field
  (`structured_diagnostics`) alongside the legacy `Vec<String>`. Add
  `EmitWalker::push_typed_diag(code, message)` and
  `EmitWalker::take_typed_diagnostics()`. Wire the drain in `cmd_build.rs`
  after `emit_walker.walk(...)`.
- Establishes the ONE canonical path for any new EmitWalker T-code. The
  legacy `Vec<String>` is not migrated in this pass — that is a follow-up
  that requires per-site triage (does this T-code fire on any test
  fixture? if so, is it a real bug or a false positive?). Doing that
  triage inside this refactor is scope surprise.
- Invariant introduced: any `Diagnostic` pushed via `push_typed_diag` is
  guaranteed to reach the sink.
- Bug class: eliminates silent-fire-then-discard for all FUTURE push
  sites. Existing `Vec<String>` pushes remain silent; retirement is
  a follow-up documented at the bottom of this file.
- Test strategy: add an elaborator-lib unit test that verifies
  `push_typed_diag` + `take_typed_diagnostics` round-trips a T-code
  faithfully; keep all four suites green.
- Reversibility: contained; the new field/methods are additive.

**FLOOR: if Step 3 lands and nothing beyond, no NEW EmitWalker T-code
can be silently discarded — the canonical typed pipe exists and is
wired to the sink. The legacy string buffer remains a known technical
debt (see follow-ups) but adding new push sites through it is now the
non-canonical path.**

### Step 4 — Deferred: encoder-imposed drift is documented, not a smell

- Original intent: retire `estimated_offset +=` bypass in
  `emit_visit_lambda.rs:841-842` and `emit_let.rs:102-103`.
- Reason deferred: both sites carry a `NOTE(step5)` explaining the pin:
  the encoder emits `48 B8 imm64` (10 bytes) for `Mnemonic::Mov [Reg,
  Imm64]` even when the value fits `imm32`-sign-extended (`48 C7 C0
  imm32` = 7 bytes). Numerous tests pin the 7-byte form. Migrating to
  `emit_inst` uses `estimated_bytes` — which returns 10 — and would
  break those tests. The correct retirement path is to give the encoder
  a smaller-form option (or introduce a MovSized-style variant like the
  W8/W16/W32 path already has). Both are out of scope for a refactor
  that must keep the tree green. Moved to follow-ups.

### Step 5 — Deferred: `loop_contexts` has no production consumer

- Original intent: RAII `LoopContextGuard` on visit_while / visit_loop.
- Reason deferred: `rg fn visit_break | IrKind::Break` finds no
  production consumer — the `current_loop_context` accessor is called
  only from `emit_walker_tests.rs`. The visitor never lowers Break; the
  push+never-pop pattern is a smell but not a live regression source.
  A proper fix requires wiring `visit_break` + a real tree-walk (not
  post-order over the flat arena) — larger than a refactor step. Moved
  to follow-ups.

### Step 6 — Fold `visit_field_access_with_reg` into `visit_field_access`

- File: `crates/paideia-as-elaborator/src/emit_field_access.rs`.
- Two ~100-line near-clones (`:28-131` vs `:328-431`) that differ only in
  destination register. Fold into `visit_field_access(id, arena,
  dest: Option<RegId>)` defaulted to RAX.
- Also inline the redundant record-layout probe in `emit_visit_lambda.rs:169-203`.
- Invariant restored: one place emits the field-access load.
- Bug class: divergent behavior when one clone is updated but not the
  other.
- Test strategy: all four suites.
- Reversibility: contained.

### Step 7 — Extract `BindingEnvironment` for lower.rs populators

- File: `crates/paideia-as-elaborator/src/lower.rs`.
- The `binding_name → struct_type_text` map at
  `populate_field_access_info:1125-1174` and the near-identical
  `binding_name → enum_type_text` map at `populate_match_arm_meta:1444-1500`
  are duplicated. Hoist a `BindingEnvironment { struct_bindings,
  enum_bindings }` computed once at the top of `lower_ast_to_ir` and
  threaded to both populators.
- Invariant introduced: one source of truth for binding-type resolution.
- Bug class: two-populator drift; adding a Let-shape fix in one place
  but not the other.
- Test strategy: all four suites.
- Reversibility: contained inside `lower.rs`.

### Step 8 — Deferred: entry-symbol finalization invariant

- Original intent: assert `entry.offset < text_bytes.len() && entry.size
  > 0` in `build_elf_object` + `build_pe_object`, and emit a new B-code
  diagnostic on violation.
- Reason deferred: the fix requires (a) a new diagnostic registration
  in `catalog.toml`, and (b) touching two divergent format paths (ELF +
  PE) that already handle function-offset resolution differently
  (survey finding: PE discards `offset_map` at cmd_build.rs:2738). Doing
  both inside a refactor step risks the "small change → PE-only
  regression" pattern this refactor is trying to reduce. Moved to
  follow-ups; the correct home is a shared `finalize_symbols` step
  consumed by both back-ends.

### Recommended follow-ups (out of scope for this pass, filed for a later
autonomous pass)

- **Cmd_build phase extraction.** The 1,448-line `run` function begs for
  extraction into a `BuildPipeline` struct with named phase methods. This
  is genuinely large and needs its own softarch pass; it is not attempted
  here. Highest structural ROI, highest churn.
- **PopulatorPass trait with declared provides/requires.** After the
  BindingEnvironment step above, we have the beginnings of a shared
  input; extending it to a full manifest is the natural next step.
- **Scrutinee-load helper in `visit_match`.** The adversarial finding
  (const-folded scrutinee) is genuinely a correctness bug and requires
  emitting a real memory load with a relocation against the scrutinee's
  binding. This is a correctness fix, not a structural refactor; it is
  the natural next step after the diagnostic sink is unified so that any
  new T-code fired during the fix is visible.
- **Retire five arena-full-scans in `cmd_build::run`.** Fuse the
  `literal_values`, `binding_names`, `public_lets`, `lambda_params`, and
  `name_resolution` scans into a single AST-index pass. Cuts arena scans
  from 7 to 1.
- **Merge label side-tables** (`labels` vs `label_to_instr`) into one
  typed accessor family. Two disjoint tables with disjoint writers is a
  smell.
- **Rewire or remove dead walkers** (`MutationWalker`, `LifetimeWalker`,
  `BorrowWalker`) with orphan diagnostic buffers.
- **Register the 12 uncatalogued T-codes** or delete emissions:
  `T0500, T0501, T0503, T0504, T0506, T0510, T0550, T0553, T0554,
  T0555, T0556, T0557`.

1. `cargo build --release -p paideia-as`
2. `cargo test --release -p paideia-as-parser --lib`
3. `cargo test --release -p paideia-as-elaborator --lib`
4. `cargo test --release -p paideia-as`

`boot_orchestration_v2_smoke`, `pa_r17_010_record_fnptr_reloc`,
`abi_pdx_parses_cleanly`, all `build_emit_*` tests.
